# Dialoo: GitHub -> Render deployment

## What goes to GitHub
Commit `apps/api/src`, `apps/api/pom.xml`, `apps/api/Dockerfile`, `apps/api/.dockerignore`, `apps/web/src`, `apps/web/public`, `apps/web/package*.json`, `apps/web/vite.config.js`, `apps/mobile` source/config (except ignored generated files and secrets), `render.yaml`, documentation, and `*.env.example`.

Never commit `.env`, actual passwords, access tokens, keystores, `node_modules`, `dist`, `target`, build outputs, or `.git` inside a ZIP. Review `git status` and `git diff --cached` before pushing.

## GitHub (PowerShell, from extracted project root)
```powershell
git init
git branch -M main
git add .
git status
git diff --cached --name-only
git commit -m "Prepare Dialoo for Render deployment"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main
```
Create the empty GitHub repository first. If origin exists, use `git remote set-url origin ...` instead.

## Render
Create a Blueprint from the GitHub repo and use `render.yaml`. It provisions a Docker API and a static React website. Database is external MySQL 8; Render does not provision MySQL here. Set all `sync: false` variables in Render's dashboard.

API: DB_URL (JDBC MySQL with TLS), DB_USERNAME, DB_PASSWORD, ADMIN_PHONE, ADMIN_PASSWORD, FRONTEND_ORIGIN (actual Render web URL), GEO_USER_AGENT. JWT_SECRET is generated by Blueprint. Set OTP_DEV_MODE=false and configure a real SMS provider before real users. Do not set demo Flyway locations in production.

Website: VITE_API_BASE_URL=https://YOUR_API.onrender.com/api/v1. Vite variables are public in browser bundles: never put secrets there. Redeploy website after setting this value. Set API FRONTEND_ORIGIN to actual website URL and redeploy API.

Health: https://YOUR_API.onrender.com/api/v1/health ; also check `/actuator/health`. Ensure database network/firewall allows Render outbound connections.

## Important security notice
The original uploaded archive contained a database password embedded in `application.yml`. It has been removed from this copy, but **rotate that password at the database provider before pushing**. If it was committed to any previous remote Git history, removing it from the current file is not sufficient: rotate it and consider history cleanup.

## Flyway
`SPRING_FLYWAY_LOCATIONS=classpath:db/migration` loads versioned migrations only. Demo SQL is excluded. Check migration compatibility with the existing database/Flyway schema history before deploying; back up production DB.

## Verification
Run `mvn test` in `apps/api`, `npm ci && npm run build` in `apps/web`, and `git status --ignored` for an ignore audit. Docker build from root: `docker build -f apps/api/Dockerfile -t dialoo-api ./apps/api`. These builds are not executed in this packaging step.
